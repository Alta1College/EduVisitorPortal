# Edu Visitor Portal v1.0.1

A bug-fix and security release for v1.0.0. It fixes problems found in a code review of v1.0.0
(issues #1–#8) and updates Symfony for the November 2026 security advisories. No new features.

**Update from v1.0.0 promptly**: the emergency and data-retention fixes matter for safety and
for legal holds.

## Fixes

### Emergencies
- **A real emergency during a drill** (#1). A drill left open used to block a real emergency
  roll call: pressing start returned the drill, so no fresh list was taken and no emergency
  messages were sent. Now the drill ends and an emergency roll call starts in its place, with
  everyone signed in now, the marks wardens already made, and the emergency SMS and email sent
  once. A **Real emergency** button appears on the on-site page and the drill's board while a
  drill is open.
- **Emergency SMS retries** (#2). If the SMS provider is briefly unreachable or answers with a
  temporary error (timeout, 429, 5xx), texts stay "sending" and are retried for about two
  minutes instead of failing at once.
- **Delivery status** (#2). A delivery receipt that arrives while the message is still being
  sent can no longer be overwritten with an older status.
- **Emergency emails are sent once** (#2), even when the same email is queued twice.

### Data retention
- **Legal holds without an end date** (#3). Photos and documents of visits under an indefinite
  legal hold were deleted by the evidence purge. Visits and evidence now follow the same hold
  rule.
- **Credential holders who have never visited** (#3), for example imported screening-check
  records, are no longer deleted as orphan visitors together with their credentials.
- **Report recipients per site** (#3). A site can now switch a report off by entering `none`;
  an empty site field still follows the organisation.

### Settings and reports
- **Settings are validated again** (#7). An invalid auto sign-out time used to save as success
  and silently stop automatic sign-out; mistyped report addresses were dropped. Times,
  recipient lists and other patterned settings are now checked when saved.
- **CSV exports** keep phone numbers such as `+61 412 345 678` unchanged; formulas are still
  neutralised (#7).
- The English visit page no longer shows German "bis" in time ranges (#7).
- Three permissions checked by the access rules (`ViewAny:Monitor`, `EditSite:Visit`,
  `DeleteSite:Visit`) now exist, so custom roles can be given them (#7). No built-in role
  changes.

### Release and documentation
- The demo start scripts stop with a clear message when run from a source checkout (#8).
- The README explains how to build the image if pulling it is refused (#8).
- Updated upgrade and rollback guidance, security policy and version references; a question
  form replaces the link to the disabled Discussions (#8).

### Security
- Symfony components updated to 8.1.12 for the advisories published on 2026-11-25
  (html-sanitizer, http-client, http-kernel, mailer, routing, serializer).

## Updating from v1.0.0

Follow the update steps in [deployment.md](../deployment.md#updates). For this release:

- **No database migrations.**
- **Run the permission sync** once after the new image is running:

  ```bash
  docker compose -f docker-compose.prod.yml exec --user www-data app php artisan visitorportal:sync-permissions
  ```

- **Check your settings.** Settings are now validated when saved. Open Organisation settings
  and each site's settings once after updating; if a time or address list was saved in an
  invalid format, the page will ask you to correct it when you next save.
- Rollback to v1.0.0 is a plain image rollback (no schema changes). The permissions added by
  the sync can stay.

## Container Image

```text
ghcr.io/alta1college/eduvisitorportal:v1.0.1
```

For the production `.env`:

```env
VISITORPORTAL_IMAGE=ghcr.io/alta1college/eduvisitorportal:v1.0.1
```

## Not in this release

Further hardening from the same review (deployment, CI and application hardening, issues #4–#6),
names in the audit log (#3), and the remaining scheduling and timezone items in #7 are planned
for a later release.
